## Continuation
What a train starts from is one rule across sites (`init`, `init_mode`): without either, the adapter this session trained last is
continued (its lineage goes on); nothing trained yet means a fresh LoRA. `init` alone is the site's native continuation (stated in
its row). `init_mode` makes it exact: `resume`, `branch`, `fresh`. Every `call.json` / `training.json` records `continuation`
(`kind`, `parent`, `state_restored`, `parent_checkpoint_id`, `resume_from_step`), `lineage_id` (minted when a lineage starts, kept by
resume / continue, new on branch / fresh) and `checkpoint_id` (the weights' digest); the job result's `receipt.lineage` repeats
them. A `resume` whose parent's full state is gone is refused with that fact (start from its weights with `branch` instead). No
default picks an adapter by score: "last trained" is the one you trained most recently.

## Failures
A request this site cannot run as written ends `failed` in `jobs/<id>.json` with this text; nothing is charged:
- `train: unsupported spec field(s) ['<field>', ...]; this site reads only: steps, lr, batch, seed_start, reward, init, start_preset, start_mix, note, goal, time, rollouts, seeds, init_mode, weights, task, name, data, objective, epochs, min_reward, stop_when, score_center`
- `train: rollouts must be 8 or 16 (rollouts per prompt, the GRPO group size), got <value>: ...` (an integer; 16.0 or true is refused too)
- `train: seeds: <reason>` when `seeds` is malformed (`'<part>' is not a seed or a range a-b`, a range that runs backwards, a non-integer entry), names a hidden seed (`<s> is a hidden seed; seeds 1-100 are reserved ...`) or is too short (`<n> seeds for a call of <m> rollouts (steps x batch x rollouts); give at least <m>`); `train: seeds cannot be combined with <field>: <why>` with `data`, `start_preset` or `start_mix`
- `train: task must be one of ['lift', 'nut', 'restack', 'revstack', 'stack', 'wipe'], got '<task>'` (twolift, handover, stackv2 have no practice unit here)
- `train: init adapter not found: <path>`
- `train: reward must be 'task_completed', 'shaped' or the path of a .py file defining reward(result) -> float`
- `train: reward file <path> is outside your workspace; a reward file must be a file in your workspace` (a symlink is not followed either)
- `train: name: letters, digits, _ . - (max 48)`
- sft: `train: data line <N>: <rule>` (a row's keys, task, seed reserved, prompt, program or reward), `train: no row has reward >= min_reward <m> ...`, `train: field(s) [...] have no meaning with objective 'sft'; ...`, `train: objective 'sft' needs data: ...`, `train: objective 'sft' trains the small policy profiles on this site ...`, `train: steps <s> != ceil(kept rows x epochs / batch) = <n>; omit steps`, `train: task: an sft spec trains the tasks of its kept rows (...); omit task`
- `train: data line <N>: <rule>` for a row that breaks a rule above (not a JSON object; unsupported key(s); task must be one of ...; seed must be an integer; seed <s> is reserved ...; variant of '<task>' must be one of ...; prompt must be a non-empty string; prompt has <n> characters), or `train: data file has no rows` / `data has more than 4096 rows` / `data file is <n> bytes; at most 16777216`
- `train: data has <rows> rows, not a multiple of batch <batch>: ...` / `train: steps <s> != data rows / batch = ...; omit steps` / `train: task: a spec with data trains the tasks its rows name (...); omit task` / `train: note cannot be set with data; ...`
- `train: data file <path> is outside your workspace; a data file must be a file in your workspace` (a symlink is not followed either)
- `train: batch <b> does not split equally across <n> tasks [...]; use a multiple of <n>` / `train: task: each task at most once, got [...]` / `train: note edit one task's training prompt; a spec naming several tasks cannot set them` (a `task` list)
- `train: task 'revstack' runs its simulator under a scene shift and practises alone; name it in a spec of its own`
- `train: your reward function raised <Error>: <message> (reward.py line N); ...` / `train: your reward function tried to <action> (<detail>), which the reward sandbox refuses; ...` / `train: your reward function ran longer than 120 s on one rollout ...`: a custom `reward(r)` runs in a sandbox, once per rollout: plain Python and the interpreter's libraries (math, json, numpy), files only in its working directory (temporary), no other files, no network, no subprocesses, 60 s CPU and 4 GiB per call. The train stops at the first such failure.
- `train: seeds 1-100 are reserved for the final score; use dev seeds >= 800001`
- `train: stop_when...` for a `stop_when` that breaks a rule of Early stop above (the message names the rule)
- B2: `train: start_preset '<p>' is a registry preset, built with the privileged oracle; on a hidden task build your own start states with preset.py ...` / `train: start_preset '<p>' was built on task another task, not <task>`
A failure inside the trainer or the simulator (crash, missing adapter files, a hidden seed used) ends the session as an infrastructure
fault. An all-zero update is a training outcome, shown on the scoreboard: the adapter's change is zero, so it behaves as its init (base or the init adapter).

## Progress and cancel
While a train runs, its record shows completed steps, the latest step's mean reward, the fraction of rollouts with reward > 0
and canonical GPU-hours of the steps done so far (read from the trainer's per-step output about once a minute). A checkpoint is saved every
step. A call stopped by the cluster (time limit, preemption, node failure) continues from its last checkpoint in a new Slurm job, at most 3 times; its status then says `continued from step k in job J`, and its result lists every Slurm job (`jobs`) and each continuation (`continued`: `job` stopped, `cause`, `from` step, `of` steps, `continued_in` job), as it lists site retries.
`cancel.py ID` stops the job and keeps the adapter of the last saved step (registered with the steps it ran), or ends the
job `failed` if none was saved; either way the job is charged the canonical cost of the steps it completed (see Cost).

## Cost (canonical GPU-hours)
The budget is charged a canonical cost per call, the same whatever hardware the site runs the call on. The tables below are
the Qwen3.8-27B policy's; with another policy the costs differ, and SCOREBOARD.md's "Expected cost per call" line gives them.

| call | canonical cost |
|---|---|
| train, 1 step | 0.39 |
| train, 10 steps | 1.98 |
| train, 30 steps | 5.50 |
| train, 10 steps, `rollouts` 16 | 3.74 |
| train, N steps | 2 x (0.1079 + 0.0881 x N x batch / 8 x rollouts / 8) |

| eval of one task on | 5 seeds | 20 seeds | 100 seeds |
|---|---|---|---|
| canonical cost | 0.15 | 0.19 | 0.45 |

An eval's cost is mostly its fixed part, so 100 seeds cost little more than 5. A call that fails or is cancelled is charged the
canonical cost of the steps it completed, or less if it ran only briefly. The cost is also the admission estimate.
