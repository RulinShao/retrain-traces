# Design (pass 1)

## Change
`specs/lift1.json` — one GRPO train on `lift` from base (no init):
- `reward: task_completed` (binary, matches the scored metric exactly)
- `steps: 30, batch: 8` (64 rollouts/step; 1920 rollouts total), default `lr 2e-5`
- training seeds 810001+ (default) — disjoint from dev-eval (800001+) and hidden (1-100)
- `note` (training prompt only, never in eval): steer exploration toward robust
  programs — retry segmentation via Molmo point prompt on empty text-prompt masks,
  explicit camera->world conversion of the grasp pose, open + above-target approach
  with height margin before descending, close + lift, stay in workspace.
Against: base policy (67/100 on dev 800001-800100).

## Expected observation
- Training: per-step `score_mean` should start near ~0.65-0.7 (base-level program
  quality on training seeds) and climb over 30 steps; `frac>0` near 1.0;
  `failure_stages` concentrated in `task` (grasp/execution), not `sim`/`program`
  crashes. If score_mean stays flat or crashes dominate, the hypothesis that "more
  robust program structure" is learnable is weak -> cancel and reconsider.
- Dev (held-out, fresh seeds 800101+): lift1 should beat base's 67 at the same n.
  Ship lift1 if its 100-seed count >= base's 67 (posterior mean otherwise favors
  base); ship base if lift1 < 67.

- total committed: 7.32; remaining after: 0.68 (covers one 5-seed spot check, 0.36)
- hedge: Checkpoint at step 10 — if the step-10 trend is bad, cancel (charged ~4.03
  for 10 steps) leaves ~3.5 for a redesigned smaller run.
