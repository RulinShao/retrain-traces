Build start states for practice on task T, saved per source seed and kept only if every state restores. Then a train spec with
"start_preset": "NAME" on task T starts each practice rollout from those states. Two ways to pick the states:
  * prefix program (--program FILE --seeds N): your prefix program (a .py in your workspace, written with the task's own API, the
    functions in its eval prompt) runs once on each of N fresh dev seeds (1-32) on T's simulator, and the state it reaches is saved.
  * from rollouts (--from rollouts/<job>.jsonl --where "<predicate>"): the end state of each episode of a prior rollout job of
    yours on T that the predicate matches (at most 32) is saved, at that episode's own dev seed. The rollout itself kept no
    restorable state, so each matched episode's program is run again at its seed on T's practice simulator and the state it
    reaches is the one saved (compare the record's log_tail with the rollout's stdout_tail to see whether the re-run went the
    same way). --where is a python expression over each rollout row r, e.g. "not r['task_completed']"; it is evaluated in the
    reward box (never imported).
The record (per seed: seed, sandbox_rc, secs, wall_s, log_tail, restorable, drift_mm, error; and your program, or the --from /
--where source) is written to presets/NAME.json. Charged as an eval of the seeds built. Refused before anything runs: a program
that names a privileged API or the simulator's objects; a --from whose matched rows include a hidden seed."""
