# Playbook
version: 16 (2026-10-27; fair-sc-3 + hyak trace reviews #9/#10)
Past-session experience (with its condition) to test here; not this session's facts (see tool docs). Numbers/sources: skills/shared/EVIDENCE.md (other sessions and settings: not targets). Gate: one session = unconfirmed; a 2nd session or a hidden-seed score confirms; dropped after two testable batches. Edits -> playbook_suggestions.md.

Observations to test:
1. A base-0 task gave no completion signal and shaped reward never lifted one (confirmed); count task_completed rollouts (shaped>0 is not a completion) before spending on it.
2. Training one task shifts others; and the submitted adapter serves EVERY task, so it can regress one you never evaluated (incl. eval-only, base 0). Eval a candidate and the FINAL stack on every task before submitting.
3. On equal-reward rollouts, changing the start state or reward beat training longer.
4. Adapter pairs combined well and badly -- evaluate each adapter alone AND the pair in one batch. One session chained (train B from A's adapter) to compound gains where fresh adapters only paired (unconfirmed).
5. Gains flattened after moderate steps -- read the curve before extending. One run kept past its peak (reward falling) lost its gain and hurt other tasks (unconfirmed); cancel keeps the last saved step.
6. Training-seed scores and held-out dev evals have differed; prefer the held-out number.
7. Queues took hours; submit the jobs wanted together then wait in LONG windows (waiting isn't charged), not short re-polls.
8. Keep the best checked stack loaded as you go, so a cut-short session still has one.
9. Plan the budget up front (reserve checking evals/loads); commit early to tasks with signal.
10. The biggest gain came from training the highest-HEADROOM task (low base, real signal), not the strong ones (unconfirmed).
11. A second train on another signal-bearing task added to the first; stopping while a train+checks still fit left it untested (unconfirmed).
12. An eval that ended with no count says nothing about the adapter; a rerun cost less than dropping it (unconfirmed).

Did not work in earlier sessions:
- A practice start state the evaluation never uses (cube already in hand): almost no successful rollouts.
- A training-only note did not carry to evaluation; it edits only the prompt text (trainer doc), not the task trained.

=====README=====
# Shared skills (new line: retrain_min and retrain_fixed)

Optional, agent-facing scripts and notes. Pass this directory with `--skills skills/shared` to either harness: it is
copied into the workspace as `skills/optional/` (apart from the mandatory tool docs in `skills/tools/` and
`skills/trainer/`) and the system prompt gains two lines (where they are; append lessons to playbook_suggestions.md).
`PLAYBOOK.md` (<= 2,500 characters, versioned) is also inlined into the system prompt under "Playbook
(skills/optional/PLAYBOOK.md: optional advice from earlier sessions; you may follow or ignore it)"; the session records the version
(RESULT.json `skills_version`, SCOREBOARD.md header). Nothing else changes; the agent may use, edit or ignore them.
A skill is a directory with a SKILL.md and, optionally, scripts that run in the workspace with no other service.

| skill | what it does |
|---|---|
| `EVIDENCE.md` | the session paths and eval rows behind each confirmed PLAYBOOK.md item, by section |
| `reward_check/` | `check_reward.py REWARD [--results FILE]`: runs your reward(result) on example (or your own) sim replies and prints the scores |

The other directories under `skills/` (decompose, library, reward_check, snapshot, train_grpo, write_practice,
write_skill, gateway.py, README.md, ADAPTERS.md) are the frozen old loop's seed skills: they call `skills/gateway.py`,
which only `retrain/` serves, and they stay in place because `retrain/workspace.py` (SEED) and `envs/` job scripts read
them by path. See `../OLD_LOOP.md`.
