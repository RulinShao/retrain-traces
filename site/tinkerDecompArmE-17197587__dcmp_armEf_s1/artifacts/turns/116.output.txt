64:## Training data (`data`)
65:`data` names a JSONL file in your workspace (a path relative to the workspace, or absolute inside it): one line per training
66:prompt, `{"task": ..., "seed": ..., "variant": ..., "prompt": ...}` (`variant` and `prompt` optional, no other keys):
67-- `task`: a trainable task. `variant`: another trainable task of the same simulator task (e.g. `stack` with variant `revstack`; revstack runs under a scene shift and practises alone, so a dataset with revstack rows has no rows of any other task); the row then
68-  trains on `variant`. Any mixture of tasks and variants is allowed.
69-- `seed`: an integer >= 810001 (seeds 1-100 are the final score's, 800001-809999 are eval.py's dev seeds); all `rollouts`
70-  rollouts of the row run on that seed.
71:- `prompt`: replaces the task's user message for that row only (the system message stays). A row without `prompt` trains on
72:  the task's eval prompt, checked byte for byte before training; a row with `prompt` is not checked and counts as a prompt
73:  override, a method choice recorded with the adapter (`data.prompt_overrides` and `data.label` in training.json).
74-- Rows train in file order, `batch` rows per step: the row count must be a multiple of `batch`, and the call runs
75-  rows / batch steps (omit `steps`, or give that number). The call's tasks come from the rows (omit `task`); `note` and
76:  `goal` are not accepted with `data`. At most 4096 rows, 16 MB, 65536 characters per `prompt`.
77:- The file is copied when the call starts; training.json's `resolved_spec.data` and the train's result (`config.data`) record
78:  its `sha256`, `rows`, rows per task (`tasks`) and `prompt_overrides`.

80:## SFT (`objective: sft`)
81:A spec `{"objective": "sft", "data": "<file>.jsonl"}` (optional: `name`, `init`, `epochs` (1), `batch` (16 rows per step), `lr`
82:(1e-4), `min_reward` (1.0), `time`; no other field) trains the policy's LoRA by supervised fine-tuning (cross-entropy on the program's
83-tokens only; LoRA rank 32 / alpha 64 on the policy's modules, or `init` continued; without `init` it continues the policy's own init,
84-as a practice call does). It runs on the small policy profiles (SCOREBOARD.md's `policy:` line names one, e.g. Qwen3-8B).
85-Availability is per policy profile: the session's turn-0 facts state it (`train objectives for this session's policy (...)`).
86:- Each line of `data` is `{"task": ..., "seed": ..., "prompt": [{"role": "system" | "user", "content": ...}, ...], "program": ..., "reward": ...}`
87:  (exactly these keys): `task` a trainable task (a hidden task by the name you see), `prompt` the chat the program answers (the user
88:  message last; `tasks/<task>/eval_prompt.txt` as messages is the eval prompt of record), `program` the response trained on, `reward`
89-  a number used only as the `min_reward` filter.
90-- `seed` is the scene the program ran on: seeds 1-100 (the final score's) and 800001-809999 (eval.py's dev seeds) are refused, so
91-  no reading you or the final score take is on a scene the policy was fitted on.
92:- A kept row whose prompt is not the task's eval prompt of record is a prompt override (a method choice): counted in
93:  `data.prompt_overrides` and labelled, as `note`/`goal` are.
94-- Steps = ceil(kept rows x epochs / batch); rows train in a fixed shuffled order; a row longer than 4096 tokens is dropped (`call.json`
95:  `sft_facts.dropped_too_long`). At most 20000 rows, 256 MB, 65536 characters per message or program.
96:- Building the file: `python3 skills/trainer/sft_rows.py practice adapters/<name> [--min-reward 1] [--steps 3-5] > sft.jsonl` takes a
97:  finished practice call's rollouts (Output below); `python3 skills/trainer/sft_rows.py rollouts rollouts/<id>.jsonl [--min-reward 1] > sft.jsonl`
